# Repository research notes

Checked 2026-10-26 against the public repositories and skill pages below. Behavior describes the inspected public version, which may change. These notes identify useful ideas and differences; no third-party code or passages were copied into the skill.

| Repository | Verified behavior | Design lesson used here |
| --- | --- | --- |
| [thoughtbot/atomic-commits-plugin](https://github.com/thoughtbot/atomic-commits-plugin/blob/main/skills/atomic-commits/SKILL.md) | Exists. Its skill asks agents to plan steps, commit after each step, stage selectively, and consider splitting around roughly 200-line PRs. The repository also documents a diff-size nudge hook. | Coherent, working increments and separable preparatory work are useful; a line target and automated commits do not match this user's control preference. |
| [AkshitIreddy/agent-skills atomic-commits](https://github.com/AkshitIreddy/agent-skills/blob/main/skills/atomic-commits/SKILL.md) | Exists. It advises one coherent concern, a usable state, selective staging, relevant checks, staged-diff review, and Conventional Commits while allowing agents to create commits within authorization. | Preserve unrelated user work; group dependent code and tests; treat commit count as a judgment call. |
| [qubernetic/git-workflow-agent-skill](https://github.com/qubernetic/git-workflow-agent-skill/blob/main/SKILL.md) | Exists. It enforces Gitflow branches, issue-driven work, Conventional Commits, semantic versioning, and PR-only merging, and includes operational Git instructions. | Clear conventions can aid message advice, but one project's strict Gitflow policy should not be imposed on a beginner's practice projects. |
| [JacobDavidAlcock/git-commit-chunker](https://github.com/JacobDavidAlcock/git-commit-chunker/blob/main/SKILL.md) | Exists. It inspects status and staged/unstaged diffs, groups changes, then stages and commits them and pushes afterward. Its README mentions optional push, while the inspected SKILL.md directs a push as its final step. | Base advice on observed Git state and distinguish staged from unstaged changes; omit its Git mutations and fixed category-based commit order. |
| [wanderlima/agent-skills prepare-git-commit](https://github.com/wanderlima/agent-skills) | Exists according to the repository's current README, which lists the skill under `skills/git/prepare-git-commit/`. The README says it stages related changes and writes `.git/COMMIT_EDITMSG`, leaving `git commit` to the user. The individual SKILL.md could not be retrieved during this check, so its finer behavior is unverified. | A human handoff is useful, but even staging and writing Git metadata exceed this advisor's boundary. |

The advisor's specific combination—read-only observation, explicit timing verdict, hunk-level suggestions, novice explanations, and human-only Git writes—is an original design based on the user's stated workflow.
